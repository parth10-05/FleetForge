# Contributing to FleetForge

1. Read `docs/implementation-plan/00-core-principles-and-delivery-contract.md`.
2. Keep every change within an approved phase and preserve its safety invariants.
3. Run `make verify` before requesting review.
4. Do not commit credentials, firmware artifacts, real device data, generated
   evidence containing sensitive values, or local simulator state.
5. Add or update focused tests and evidence for every behavior change.

The repository has no public contribution workflow until its license and
governance decisions are approved.
